Tư duy “defend”

Với mỗi lựa chọn (chunk size, vector store, model, có rerank không…), chuẩn bị trả lời “vì sao chọn vậy, đánh đổi gì, phương án khác là gì”. Đó là điểm khác biệt giữa người xây và người chỉ dùng.

1. RAG — Retrieval-Augmented Generation

Cho LLM trả lời dựa trên tài liệu riêng thay vì chỉ kiến thức huấn luyện → giảm “bịa” (hallucination), cập nhật được và trích dẫn nguồn. Hai pha: indexing (offline) và retrieval + generation (online). RAG nay là kiến trúc mặc định (≈72% doanh nghiệp dùng trong production).

RAG pipeline. Index một lần (chunk→embed→store); mỗi truy vấn: embed → hybrid retrieve (vector + keyword, hợp nhất bằng RRF) → rerank (cross-encoder) → LLM sinh câu trả lời có trích dẫn.

Cắt tài liệu thành đoạn vừa đủ ngữ cảnh — quyết định đòn bẩy lớn nhất. Sweet spot ~256–512 token (baseline production 512–1024) với overlap 20–25%. Semantic chunking (cắt theo ranh giới ngữ nghĩa bằng embedding) cải thiện retrieval đáng kể (vd +36% F1 trên tài liệu pháp lý); hierarchical (parent summary + child detail) cho tài liệu dài. Với tài liệu kỹ thuật: chunk theo heading/section.

Biến text thành vector sao cho văn bản gần nghĩa → vector gần nhau (cosine). Model embedding khác model sinh; cùng một embedding model cho cả index lẫn query. So sánh model qua MTEB; nhiều model open-source dẫn đầu (GTE-Qwen2, E5-mistral) — hợp dữ liệu nhạy cảm self-host.

Lưu vector + metadata, tìm k láng giềng gần nhất (ANN). Hybrid search = vector (ngữ nghĩa) + keyword/BM25 (chính xác từ khoá — tốt cho mã lỗi/ký hiệu kỹ thuật), hợp nhất bằng Reciprocal Rank Fusion (RRF); thường tốt hơn vector thuần.

Sau khi lấy top-k (rộng, rẻ bằng bi-encoder), dùng cross-encoder chấm điểm độ liên quan câu hỏi↔chunk để chọn top-n đưa vào prompt. Tăng precision rõ rệt, đổi lại thêm độ trễ/chi phí.

💡

Vì sao RAG thay vì fine-tune? RAG cập nhật tri thức dễ (chỉ re-index), trích dẫn nguồn, rẻ hơn; fine-tune hợp khi cần đổi phong cách/định dạng/kỹ năng, không phải để “nhồi” kiến thức hay đổi.

2. Agentic AI

LLM không chỉ trả lời mà hành động: gọi tool, lặp, ra quyết định nhiều bước để đạt mục tiêu. Công thức: “LLM trong một vòng lặp, có tools & memory”. Ba dấu hiệu: tool use, multi-step loop (act→observe→decide), goal-directed.

Vòng lặp agent (ReAct). LLM phát tool call có cấu trúc (function calling) → runtime chạy → observation quay lại context → LLM quyết bước tiếp. Phải có giới hạn vòng vì agentic tốn token gấp 10–20× một query thường.

2.1 Multi-agent orchestration

Chia bài toán cho nhiều agent chuyên biệt (planner, researcher, coder, reviewer); một orchestrator điều phối: routing, sequencing, chia sẻ context, failure recovery — chạy song song khi độc lập, tuần tự khi phụ thuộc. Frameworks: LangChain, AutoGen, CrewAI, n8n. Ưu: chia để trị, context mỗi agent gọn. Nhược: phức tạp, tốn token, khó debug → chỉ dùng khi đủ lớn; tránh vendor lock-in.

🗣️

Kể được: “Tôi thiết kế agentic workflow với agents/sub-agents, skills, tool use và orchestration; làm trực tiếp với cơ chế agent-harness — context window, tool-use loop, multi-agent control — để tự động hoá tác vụ kỹ thuật lặp lại.”

3. MCP — Model Context Protocol

MCP là chuẩn mở do Anthropic giới thiệu (cuối 2024) để chuẩn hoá cách LLM/agent kết nối tool & nguồn dữ liệu — biến bài toán tích hợp M×N (M app × N tool, mỗi cặp một connector riêng) thành M+N. Client-server trên JSON-RPC 2.0; được OpenAI, Google, Cursor, Cline… adopt.

MCP. Thay vì viết connector riêng cho từng cặp app–tool (M×N), mỗi tool có một MCP server và mỗi app là MCP client (M+N). Đây là nền của Claude Code (MCP, skills, hooks).

4. Prompt & context engineering

Kỹ thuật prompt

4 phần
Context · Data · Task · Format (không phải lúc nào cũng cần cả 4).
System prompt
Định vai trò, ràng buộc, định dạng output.
Few-shot / CoT
Vài ví dụ mẫu; yêu cầu suy luận từng bước cho bài khó. Thử zero-shot trước.

Ép JSON/schema để máy parse.

Quản lý context (xu hướng chính)

Context window
Giới hạn token model “thấy” — ngân sách phải phân bổ khôn ngoan.
Context engineering
Thiết kế pipeline chọn/định dạng/lắp ráp đúng thông tin vào cửa sổ runtime (retrieve, tóm tắt, memory) — không nhồi tất cả.
Prompt caching
Cache phần lặp lại (system, tài liệu) → giảm chi phí & độ trễ rõ rệt.
🎯

Câu “đắt”: “Đa số lỗi đến từ ambiguity chứ không phải model. Context window là tài nguyên khan hiếm; việc của context engineering là tối đa signal-to-noise — retrieve đúng, nén phần thừa, cache phần ổn định, và pin model snapshot để hành vi ổn định giữa các version.”

5. LLM governance & cost (việc bạn vận hành)

Chi tiêu LLM API doanh nghiệp tăng vọt (≈$3.5B cuối 2024 → ≈$8.4B giữa 2025); gốc rễ là attribution (gắn token với team/use case), không phải đơn giá. Agentic multiplier (10–20× token/tác vụ) làm chi phí bùng nổ nếu thiếu governance.

Governance. Gateway (virtual key, budget, routing, cache) chặn chi phí trước khi vượt; observability gắn token với team/use case. 3 tầng: đo → tối ưu → quản trị.

API key & access

Phân phối key tập trung (virtual keys), gắn danh tính (Entra ID), phân quyền theo team/dự án.

Cost governance

Attribution token/chi phí theo người/team, quota & cảnh báo; model routing + semantic cache để tối ưu.

An toàn & tin cậy

Chống rò rỉ dữ liệu nội bộ; guardrail prompt injection; log & audit; eval chất lượng output.

⚠️

Prompt injection là rủi ro thật: nội dung tài liệu/web có thể chứa lệnh ẩn để “bẻ” agent. Phòng: tách dữ liệu khỏi chỉ thị, giới hạn quyền tool, kiểm duyệt output, không cho agent hành động bất khả nghịch nếu chưa xác thực.

6. “Defend” một hệ thống bạn build

Chuẩn bị kể sâu hệ RAG hỗ trợ hotline ticket / requirement tracing theo khung kiến trúc + trade-off:

Nối tài liệu nội bộ, ticket, tri thức kỹ thuật để trả lời hotline & trace requirement. Thách thức: thuật ngữ kỹ thuật, mã lỗi, tài liệu dài.

  • Chunk theo cấu trúc + overlap → giữ ngữ cảnh kỹ thuật.
  • Hybrid search (vector + keyword/RRF) → bắt đúng mã lỗi/ký hiệu.
  • Rerank khi truy hồi nhiễu → tăng độ chính xác.
  • Citation nguồn → kỹ sư kiểm chứng, tăng độ tin.
  • Prompt caching phần tài liệu/system ổn định → giảm chi phí.

Rerank/hybrid tăng độ trễ & chi phí; cân bằng với trải nghiệm. Chất lượng phụ thuộc tài liệu nguồn. Phải có guardrail chống injection & rò rỉ dữ liệu.

Đánh giá bằng RAGAS (recall/relevance/faithfulness); tỉ lệ câu trả lời được chấp nhận, thời gian xử lý ticket giảm, adoption của kỹ sư, chi phí/token mỗi truy vấn, TTFT.

7. Trước (~2020) → Nay — bức tranh AI ứng dụng

🤖 Từ “prompt khéo” sang hệ thống có engineering & governance
⏪ Trước (~2020)

NLP theo model riêng từng task; “prompt engineering” = mẹo câu chữ; chưa có RAG/agent chuẩn; chi phí & governance ít được nói tới.

⏩ Nay (2025–2026)

Chuyển sang context engineering + RAG + agentic + MCP chuẩn hoá tool; vai trò “prompt engineer” đơn lẻ mờ đi, thay bằng kỹ năng thiết kế context + viết eval + cost/governance (attribution, routing, EU AI Act/ISO 42001).

Vì sao quan trọng: đúng vai trò AI Platform của bạn — bạn không “gọi API” mà vận hành attribution, routing, governance & agentic harness. Đây là phần “defend” mạnh nhất.

8. Tự kiểm tra

Khi nào RAG, khi nào fine-tune? Áp dụng▾

RAG khi cần kiến thức cập nhật/trích dẫn nguồn (tài liệu hay đổi). Fine-tune khi cần đổi phong cách/định dạng/kỹ năng ổn định. Nhồi kiến thức hay đổi bằng fine-tune là tốn kém & khó cập nhật.

Interviewer đào tiếp
  • Có thể kết hợp cả hai không? (có — fine-tune kỹ năng + RAG tri thức)
Rerank & hybrid search giải quyết vấn đề gì? Áp dụng▾

Hybrid (vector + BM25, hợp bằng RRF) bắt cả ngữ nghĩa lẫn từ khoá chính xác (mã lỗi/ký hiệu). Rerank (cross-encoder) chấm lại độ liên quan câu hỏi↔chunk cụ thể để đẩy chunk thực sự đúng lên đầu — vá điểm yếu của vector search (bi-encoder) đôi khi “gần nghĩa nhưng không trả lời”.

Interviewer đào tiếp
  • Bi-encoder vs cross-encoder khác gì về tốc độ/độ chính xác?
Một hệ agentic gồm những gì? Vì sao phải giới hạn vòng? Định nghĩa▾

“LLM trong vòng lặp, có tools + memory”: tool use (function calling), multi-step loop (act→observe→decide), goal-directed. Phải giới hạn số vòng vì agentic tốn token 10–20× một query và có thể loop vô hạn → đốt chi phí (đã có sự cố ~$47K trước khi cảnh báo).

Interviewer đào tiếp
  • Multi-agent khi nào nên dùng, đánh đổi gì?
MCP để làm gì? Khác function calling thế nào? Định nghĩa▾

MCP chuẩn hoá tool use/function calling: biến M×N tích hợp thành M+N. Mỗi tool = một MCP server, mỗi app = client; giao tiếp JSON-RPC, client discover & gọi server. Không thay function calling mà chuẩn hoá nó → tái sử dụng & mở rộng. Là nền của Claude Code (MCP/skills/hooks).

Interviewer đào tiếp
  • Rủi ro bảo mật của MCP? (auth, credential, quyền thực thi)
Governance/cost cho một AI platform gồm gì? Kinh nghiệm▾

Ba tầng: đo (attribution token↔team/use case) → tối ưu (model routing, semantic cache, prompt caching) → quản trị (virtual keys, budget/quota, rate limit, guardrail, audit). Phân biệt enforcement (gateway chặn vượt ngân sách) vs visibility (chỉ báo cáo). Gắn danh tính (Entra ID) & compliance (EU AI Act, ISO 42001).

Interviewer đào tiếp
  • Vì sao “attribution” là gốc rễ, không phải đơn giá?
  • Model routing tiết kiệm thế nào mà vẫn giữ chất lượng?

  • Query: embed→hybrid→rerank→LLM
  • Chunk 256–512 tok, overlap 20–25%
  • Hybrid (vector+BM25/RRF) · cross-encoder rerank
  • Eval: RAGAS · TTFT p90 <2s

  • tool use · act→observe→decide · goal
  • Giới hạn vòng (token 10–20×)
  • Multi-agent: orchestrator, song song/tuần tự
