1. FMI & FMU là gì

FMI (Functional Mock-up Interface) là một chuẩn mở, độc lập công cụ (tool-independent), do Modelica Association quản lý, dùng để trao đổi và đồng-mô phỏng (co-simulation) các model động giữa nhiều tool khác nhau. FMU (Functional Mock-up Unit) là đơn vị đóng gói theo chuẩn đó: một file .fmu — thực chất là một file zip đổi đuôi.

Bên trong .fmu. Zip chứa modelDescription.xml (mô tả toàn bộ biến & khả năng) + binaries (thư viện đã biên dịch theo từng platform) + resources + (tuỳ chọn) source code. Nhờ vậy FMU chạy được mà không cần tool gốc.
FMI (giao diện / chuẩn)
Là đặc tả: định nghĩa cấu trúc file, các hàm C phải có (fmi2*/fmi3*), và schema XML. Không phải phần mềm — là “hợp đồng” để các tool nói chuyện với nhau.
FMU (đơn vị / hiện vật)
Là sản phẩm tuân theo FMI: file .fmu đóng gói một model cụ thể (vd một vECU, hay một plant model — mô hình vật lý của xe/động cơ). Một tool export ra FMU, tool khác import chạy.
Vì sao quan trọng cho vECU / automotive
Đóng gói vECU hoặc plant model độc lập tool: xuất từ Simulink/dSPACE rồi chạy trong CANoe, SIL Kit, hoặc importer bất kỳ. Cho phép ghép nhiều tool vào một mô phỏng chung (controller ở tool A, plant ở tool B) → tái sử dụng model, bảo vệ IP (chỉ giao binary), và dựng SIL/MIL/HIL nhanh.
Bảo vệ IP
FMU dạng binary chỉ lộ giao diện (biến vào/ra) chứ không lộ phương trình/source → nhà cung cấp giao model cho OEM mà giữ bí mật thuật toán.

2. Các loại interface — ME · CS · SE

Một FMU khai báo (trong modelDescription.xml) nó hỗ trợ (các) loại giao diện nào. Khác biệt cốt lõi: solver (bộ giải số) nằm ở đâu — bên trong FMU hay do importer cấp.

ME vs CS. ME: FMU chỉ cấp đạo hàm, solver nằm ngoài (importer) và điều khiển bước. CS: FMU nhúng sẵn solver, master chỉ trao đổi dữ liệu tại các communication point (macro step).
Model Exchange (ME)
FMU chỉ cung cấp phương trình / đạo hàm trạng thái (der(x) = f(x,u,t)) và giá trị output; solver nằm ngoài (importer cấp một bộ tích phân dùng chung cho mọi FMU). Ưu: một solver duy nhất → đồng bộ chính xác, xử lý sự kiện (event/zero-crossing) tốt. Nhược: importer bắt buộc phải có solver; phức tạp hơn.
Co-Simulation (CS)
FMU nhúng sẵn solver riêng; master chỉ trao đổi dữ liệu tại các communication point (macro step) qua fmi2DoStep. Ưu: đóng gói kín (IP, tool khác nhau), master đơn giản. Nhược: sai số ghép nối tại communication point (input giữ hằng trong bước), khó xử lý algebraic loop giữa các FMU.
Scheduled Execution (SE) — FMI 3.0
Loại giao diện mới trong 3.0 cho clock / real-time: môi trường (scheduler) gọi từng “model partition” theo clock (chu kỳ/sự kiện) do nó điều phối — rất hợp ghép AUTOSAR / vECU chạy theo task/tick thay vì để FMU tự tích phân.

3. FMI 2.0 vs 3.0 — điểm mới & Layered Standards

FMI 2.0 (2014) là phiên bản dùng rộng rãi nhất. FMI 3.0 (2022) bổ sung nhiều thứ đặc biệt hữu ích cho ECU / hệ nhúng:

Array variables
Biến kiểu mảng có kích thước (dimension) khai báo trong XML — thay vì phải “bẻ” thành nhiều biến vô hướng như 2.0.
Kiểu Binary
Kiểu Binary (khối byte) — nền tảng để truyền frame bus (CAN/LIN/…) hay dữ liệu nhị phân qua FMU (dùng bởi LS-BUS).
Clocks (clocked / triggered)
Đồng hồ mô tả khi nào một biến/tính toán cập nhật: periodic clock (định kỳ) hoặc triggered/aperiodic clock (theo sự kiện). Hỗ trợ mô hình event-driven / rời rạc (discrete) — rất hợp cách ECU chạy theo tick/task/ngắt.
Terminals & Icons
Nhóm biến thành terminal (cổng nối có ngữ nghĩa, vd một bus) + biểu tượng đồ hoạ → nối FMU trong sơ đồ trực quan & đúng ngữ nghĩa.
Source-code FMUs
Chuẩn hoá cách đóng gói source code để importer build lại binary cho platform target (vd cross-compile cho MCU/RTOS) — không chỉ binary dựng sẵn.
Intermediate Update
Cho phép FMU (CS) gọi callback báo giá trị giữa các communication point — master lấy được kết quả trung gian, hỗ trợ đồng bộ mịn hơn & phát hiện event sớm.
Scheduled Execution
Loại interface thứ ba (xem mục 2) cho clock/real-time — ghép scheduler ngoài.

3.1 Layered Standards (FMI-LS)

FMI 3.0 tách các mở rộng chuyên biệt thành Layered Standards — “tầng phủ” trên FMI lõi (đóng gói trong thư mục extra/ của FMU), để chuẩn hoá kịch bản dùng cụ thể mà không phình chuẩn lõi:

LS-BUS ⭐ (cực liên quan vECU)
Đóng gói giao tiếp bus — CAN / CAN FD / LIN / Ethernet / FlexRay — bên trong FMU (dùng biến kiểu Binary để mang frame + clock để định thời). Nhờ đó một vECU-FMU có thể “nói chuyện” qua bus ảo với FMU khác hay với bus simulation (CANoe, SIL Kit) một cách chuẩn hoá — không cần giao thức riêng mỗi tool.
LS-XCP
Chuẩn hoá XCP (đo/hiệu chỉnh — measurement & calibration) qua FMU → gắn công cụ calibration (vd INCA/CANape) vào vECU-FMU.
LS-Measurement (Structured Measurement / Signal)
Chuẩn hoá mô tả & xuất tín hiệu đo có cấu trúc từ FMU (đơn vị, nhóm, lịch sử) để phân tích/ghi log nhất quán.
🔗

Vì sao LS-BUS quan trọng với vECU: một ECU thực giao tiếp chủ yếu qua bus (CAN/LIN…). Muốn mô phỏng nhiều ECU cùng lúc (network) hoặc ghép vECU với bus simulation, ta cần cách chuẩn để truyền frame bus qua ranh giới FMU. LS-BUS làm đúng việc đó → vECU-FMU trở thành node bus ảo “cắm” thẳng vào SIL Kit / CANoe (bài K).

4. modelDescription.xml

Là manifest của FMU: importer đọc nó trước khi nạp binary để biết FMU có những biến gì, hỗ trợ interface nào, và khả năng (capability) ra sao. Thành phần chính:

ScalarVariable (2.0) / biến (3.0)
Mỗi biến có: tên, valueReference (số ID để get/set nhanh theo kiểu — không dùng tên khi chạy), causality, variability, kiểu (Real/Integer/Boolean/String; 3.0 thêm Float32/64, Int*, Binary, Clock), giá trị khởi tạo/đơn vị.
valueReference
Định danh số của biến trong phạm vi một kiểu. API dùng mảng valueReference[] để get/set hàng loạt (vd fmi2GetReal(c, vr, n, out)).
ModelStructure
Khai báo quan hệ phụ thuộc: outputs, derivatives (ME), initialUnknowns, và dependency giữa chúng — giúp solver/master biết thứ tự tính & phát hiện algebraic loop.
Capability flags
Cờ khả năng, vd (CS) canHandleVariableCommunicationStepSize (chấp nhận đổi h mỗi bước), canGetAndSetFMUstate (hỗ trợ lưu/khôi phục trạng thái → rollback), canSerializeFMUstate, canInterpolateInputs, maxOutputDerivativeOrder… Master phải tôn trọng các cờ này.

5. Vòng đời API (Co-Simulation, FMI 2.0)

Master gọi các hàm C của FMU theo một trình tự cố định: khởi tạo → cấu hình → vòng lặp doStep → kết thúc → giải phóng.

Vòng đời CS. Instantiate → SetupExperiment → Enter/ExitInitializationMode → vòng lặp {SetReal · doStep · GetReal · t+=h} → Terminate → FreeInstance.
#include "fmi2Functions.h"

// --- 1. Nạp FMU & tạo instance (CS: solver đã nhúng sẵn) ---
fmi2Component c = fmi2Instantiate(
    "plant",                 // instanceName
    fmi2CoSimulation,        // fmuType = Co-Simulation
    guid,                    // GUID phải khớp modelDescription.xml
    resourceLocation,        // URI tới thư mục resources/
    &callbacks,              // logger / allocateMemory / freeMemory ...
    fmi2False,               // visible
    fmi2False);              // loggingOn

// --- 2. Thiết lập experiment + khởi tạo ---
fmi2SetupExperiment(c, fmi2False, 0.0, tStart, fmi2True, tStop);
fmi2EnterInitializationMode(c);
fmi2SetReal(c, &vrParam, 1, &paramValue);   // set parameter/initial value
fmi2ExitInitializationMode(c);

// --- 3. Vòng lặp co-simulation (master điều khiển bước) ---
double t = tStart;
const double h = 1e-3;                          // communication step size (macro step)
while (t < tStop) {
    fmi2SetReal(c, vrIn, nIn, u);               // đẩy input tại communication point
    fmi2Status s = fmi2DoStep(c, t, h, fmi2True); // FMU tự chạy solver nội bộ trên [t, t+h]
    if (s == fmi2Discard) { /* rollback / giảm bước — xem mục 6 */ break; }
    fmi2GetReal(c, vrOut, nOut, y);             // lấy output sau bước
    t += h;
}

// --- 4. Kết thúc & giải phóng ---
fmi2Terminate(c);
fmi2FreeInstance(c);
🆕

FMI 3.0 khác gì: đổi tiền tố fmi2* → fmi3* (vd fmi3InstantiateCoSimulation, fmi3EnterInitializationMode), và chữ ký fmi3DoStep khác — trả thêm cờ qua con trỏ để hỗ trợ event handling & early return:

fmi3Status fmi3DoStep(fmi3Instance instance,
    fmi3Float64  currentCommunicationPoint,
    fmi3Float64  communicationStepSize,
    fmi3Boolean  noSetFMUStatePriorToCurrentPoint,
    fmi3Boolean* eventHandlingNeeded,     // FMU báo cần xử lý event
    fmi3Boolean* terminateSimulation,
    fmi3Boolean* earlyReturn,             // FMU dừng sớm giữa bước
    fmi3Float64* lastSuccessfulTime);     // thời điểm dừng thực tế

6. Co-simulation master — macro/micro step, rollback

Macro vs micro step. Master trao đổi dữ liệu tại các communication point cách nhau h (macro step); bên trong mỗi bước, solver nhúng của FMU tự chia thành nhiều micro step mà master không nhìn thấy.
Macro step vs micro step
Macro step = communication step h do master chọn (khoảng giữa hai communication point). Micro step = các bước tích phân bên trong FMU do solver nhúng tự chia nhỏ (master không thấy). Master chỉ “nói chuyện” tại đầu/cuối macro step.
Communication step size
Chọn h: nhỏ → chính xác hơn nhưng chậm & overhead cao; lớn → nhanh nhưng sai số coupling tăng (input giữ hằng trong bước). Nếu FMU khai canHandleVariableCommunicationStepSize, master được đổi h động (adaptive).
Rollback (iterative master)
Nếu fmi2DoStep trả fmi2Discard (bước không hợp lệ) hoặc master muốn lặp để hội tụ, dùng lưu/khôi phục trạng thái qua fmi2GetFMUstate/fmi2SetFMUstate (cần cờ canGetAndSetFMUstate): quay lại đầu bước rồi thử lại với h nhỏ hơn.
Algebraic loop giữa FMU
Khi output FMU-A phụ thuộc trực tiếp input FMU-B và ngược lại tại cùng communication point → vòng đại số. Master phải lặp (iterate) trong một macro step (set–doStep–get lặp lại tới hội tụ), dùng rollback để thử — hoặc phá vòng bằng một khâu trễ.
Đồng bộ thời gian
Với nhiều FMU, master đảm bảo tất cả tiến cùng tới communication point tiếp theo trước khi trao đổi dữ liệu (barrier). Với real-time / bus (SIL Kit), việc đồng bộ ảo-thời-gian là then chốt để frame & input đúng thứ tự nhân quả.
// Iterative / rollback master (yêu cầu canGetAndSetFMUstate = true)
fmi2FMUstate st = NULL;
fmi2GetFMUstate(c, &st);                 // lưu trạng thái trước bước
fmi2Status s = fmi2DoStep(c, t, h, fmi2True);
if (s == fmi2Discard) {
    fmi2SetFMUstate(c, st);              // ROLLBACK về đầu bước
    h *= 0.5;                            // thử lại với communication step nhỏ hơn
    s = fmi2DoStep(c, t, h, fmi2True);
}
fmi2FreeFMUstate(c, &st);                // giải phóng bản chụp trạng thái
⚠️

Coupling error (ZOH): trong CS, input được giữ hằng suốt macro step (zero-order hold) → xuất hiện sai số ghép nối tỉ lệ với h. Giảm bằng h nhỏ hơn, nội suy input (canInterpolateInputs/maxOutputDerivativeOrder), hoặc master lặp. Với ME thì solver chung xử lý liên tục nên không có lỗi này.

7. FMI trong vECU

Vai trò: đóng gói vECU (phần mềm ECU chạy ảo) hoặc plant model (mô hình vật lý xe/động cơ) thành FMU, rồi cho chúng chạy & ghép trong bất kỳ môi trường nào hỗ trợ FMI.

vECU + plant qua FMI. Controller (vECU) và plant model đóng gói thành FMU riêng, ghép closed-loop trong một master. Bus (CAN/LIN) đi qua LS-BUS → kết nối được với SIL Kit (bài K).
Interoperability
Vì FMI độc lập tool, cùng một plant-FMU chạy được trong Simulink, dSPACE, CANoe hay một master tự viết. OEM và supplier trao đổi model qua FMU thay vì buộc chung một tool → linh hoạt & bảo vệ IP.
vECU đóng gói FMU
Phần mềm ECU (ASW + phần BSW cần thiết) build thành FMU (thường CS, hoặc SE/clock cho định thời task). Chạy trên host runtime (bài M) để test SIL sớm, không cần phần cứng.
FMI ↔ SIL Kit
SIL Kit là bus/middleware mô phỏng phân tán; FMU (qua LS-BUS hoặc adapter) trở thành một participant trên bus ảo → ghép nhiều vECU thành mạng ECU đồng bộ thời gian ảo. Chi tiết ở bài K.
Ranh giới FMU vs FMI (dễ bị hỏi)
FMI = chuẩn/giao diện (đặc tả, danh từ trừu tượng); FMU = file .fmu tuân theo chuẩn đó (hiện vật cụ thể). Nói gọn: “FMU is to FMI as an executable is to its ABI/standard.”
🧩

SSP đi kèm FMI: nhiều FMU được nối thành một hệ thống nhờ chuẩn SSP (System Structure & Parameterization, cũng của Modelica Association) — mô tả topology kết nối & bộ tham số của cả một mạng FMU (vd nhiều vECU + plant). FMI = từng khối; SSP = sơ đồ ghép các khối.

8. Trước → Nay

🔓 Mô phỏng: khoá tool → chuẩn mở co-sim ECU/bus
⏪ Trước

Mô phỏng bị khoá trong một tool (model chỉ chạy ở Simulink hoặc dSPACE…); trao đổi model giữa OEM–supplier khó, phải dùng chung công cụ & lộ IP.

⏩ Nay

FMU là chuẩn mở — đóng gói vECU/plant độc lập tool; FMI 3.0 + LS-BUS cho co-sim cả ECU & bus (CAN/LIN/Ethernet), ghép thẳng vào SIL Kit/CANoe. Clocks/SE cho định thời tựa ECU.

Vì sao quan trọng: nói được “FMU độc lập tool, FMI 3.0 thêm LS-BUS để co-sim bus/ECU và Clocks cho định thời” cho thấy bạn hiểu vì sao FMI là mảnh ghép trung tâm của vECU/SIL, không chỉ là ‘một định dạng file’.

9. Tự kiểm tra

FMI và FMU khác nhau thế nào? Định nghĩa▾

FMI = chuẩn/giao diện mở, tool-independent (do Modelica Association quản lý) — đặc tả cấu trúc file, hàm C, schema XML. FMU = hiện vật: file .fmu (thực chất zip) tuân theo chuẩn, chứa modelDescription.xml + binaries (.dll/.so theo platform) + resources + (tuỳ chọn) source. FMI là “hợp đồng”, FMU là “sản phẩm”.

  • Cờ canGetAndSetFMUstate liên quan rollback thế nào?
Vòng đời gọi một FMU Co-Simulation? Kinh nghiệm▾

fmi2Instantiate → fmi2SetupExperiment → fmi2EnterInitializationMode → (set params) → fmi2ExitInitializationMode → vòng lặp {fmi2SetReal(inputs); fmi2DoStep(t,h); fmi2GetReal(outputs); t+=h} → fmi2Terminate → fmi2FreeInstance. Nếu doStep trả fmi2Discard: rollback qua fmi2Get/SetFMUstate rồi giảm h. FMI 3.0 đổi tiền tố fmi3 và fmi3DoStep có thêm cờ event/early-return.

Đào tiếp
  • Xử lý algebraic loop giữa 2 FMU thế nào?
  • Vì sao master cần đồng bộ thời gian?

10. Cheat-sheet 1 trang

FMI vs FMU

  • FMI = chuẩn mở, tool-independent (Modelica Assoc.)
  • FMU = file .fmu (zip)
  • Zip: modelDescription.xml + binaries + resources + (source)
  • Đóng gói vECU/plant, bảo vệ IP

Interface types

  • ME: solver NGOÀI (importer), FMU cấp đạo hàm
  • CS: solver NHÚNG SẴN, doStep tại communication point
  • SE (3.0): clock/real-time, scheduler ngoài
  • Macro step (master) vs micro step (FMU)

FMI 3.0 mới

  • Array · Binary · Clocks (periodic/triggered)
  • Terminals/Icons · source-code FMU · Intermediate Update
  • Layered Standards: LS-BUS ⭐ · LS-XCP · LS-Measurement
  • LS-BUS = CAN/LIN/Eth/FlexRay trong FMU

modelDescription.xml

  • causality: input/output/parameter/calc/local/independent
  • variability: constant/fixed/tunable/discrete/continuous
  • valueReference (ID số theo kiểu)
  • ModelStructure · capability flags

API (CS 2.0)

  • Instantiate → SetupExperiment
  • Enter/ExitInitializationMode (set params)
  • loop: SetReal · DoStep(t,h) · GetReal · t+=h
  • Terminate · FreeInstance · (3.0 = fmi3*)

Master & vECU

  • Rollback: Get/SetFMUstate (canGetAndSetFMUstate)
  • Algebraic loop → iterate/hội tụ trong macro step
  • FMU ↔ SIL Kit qua LS-BUS (bài K)
  • Chạy trên host runtime (bài M)
