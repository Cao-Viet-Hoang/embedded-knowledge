B2 Core AUTOSAR — Module (đào sâu)

Memory Stack — NvM / MemIf / Fee / Ea / Fls / Eep

Lưu dữ liệu không bay hơi (calibration, DTC, learned values…). Đi từ NvM (block/CRC/strategy) → MemIf (route) → Fee/Ea (giả lập EEPROM) → Fls/Eep (HW). Trọng tâm: vì sao cần Fee & cơ chế garbage collection + wear-leveling.

Nguồn: tên container/param/API đối chiếu AUTOSAR Classic SWS (NvM, MemIf, Fee, Ea, Fls, Eep) — xem cuối bài.

Memory stack. Mỗi tầng che chi tiết tầng dưới: NvM (logic block) → MemIf (route) → Fee/Ea (emulate/abstract) → Fls/Eep (HW). EcuM/BswM gọi NvM_ReadAll lúc startup, NvM_WriteAll lúc shutdown.

1. NvM (NVRAM Manager)

Vai trò: quản lý dữ liệu không bay hơi cho ứng dụng theo block — lo CRC, redundancy, write strategy, queue. App chỉ làm việc với Block ID, không biết flash/EEPROM bên dưới.

1.1 Khái niệm cốt lõi

Block management type
NATIVE: 1 bản, đơn giản. REDUNDANT: lưu 2 bản (đọc bản kia nếu bản này hỏng CRC) → chịu lỗi tốt hơn, dùng cho dữ liệu quan trọng. DATASET: nhiều phiên bản/index của cùng block (vd nhiều bộ cấu hình), chọn bằng index — như một mảng block.
RAM / ROM / Administrative block
Mỗi NV block có: RAM block (bản làm việc trong RAM mà app đọc/ghi), ROM block (giá trị mặc định trong flash để RestoreBlockDefaults khi NV hỏng/lần đầu), Administrative block (metadata nội bộ NvM: trạng thái, attribute).
CRC
CRC 8/16/32 tính trên dữ liệu block để phát hiện hỏng (do flash lỗi/mất điện giữa chừng). Đọc thấy CRC sai → NvM báo lỗi → app dùng redundant copy hoặc default. Đánh đổi: CRC tốn chỗ & thời gian.
Write strategy: immediate vs deferred
Immediate: ghi ngay khi gọi (dữ liệu khẩn, vd crash data). Deferred: NvM_WriteBlock/WriteAll chỉ đưa vào queue, NvM_MainFunction xử lý dần (chia tải, không chặn). Đa số dùng deferred + WriteAll lúc shutdown.
Job queue & priority
NvM xếp các yêu cầu read/write vào queue (immediate queue ưu tiên cao hơn standard queue); NvM_MainFunction rút từng job đẩy xuống MemIf. Block có thể có priority.
Explicit vs implicit synchronization
Implicit: NvM tự copy giữa RAM block ↔ NV. Explicit: app cung cấp callback NvMReadRamBlockFromNvM/WriteRamBlockToNvM để NvM gọi khi cần đồng bộ — dùng khi dữ liệu RAM do app quản lý/đổi định dạng (tránh data đang đổi giữa chừng).
Error recovery
CRC sai/đọc lỗi → thử redundant copy → nếu vẫn hỏng → RestoreBlockDefaults (ROM block) + báo. NvMWriteBlockOnce chống ghi đè block chỉ-ghi-1-lần; NvMResistantToChangedSw giữ dữ liệu qua đổi phần mềm.
ReadAll / WriteAll
NvM_ReadAll (EcuM gọi lúc startup, nạp các block đánh dấu vào RAM) & NvM_WriteAll (lúc shutdown, lưu các block đã đổi) — xử lý hàng loạt qua MainFunction.

1.2 API & cấu hình

APIÝ nghĩa
NvM_ReadBlock / NvM_WriteBlockĐọc/ghi một block.
NvM_RestoreBlockDefaultsNạp giá trị mặc định (ROM block).
NvM_ReadAll / NvM_WriteAllHàng loạt (startup/shutdown).
NvM_SetRamBlockStatus / NvM_GetErrorStatusĐánh dấu RAM block đã đổi / đọc kết quả job.

Cấu hình: NvMBlockDescriptor (NvMBlockManagement [NATIVE/REDUNDANT/DATASET], NvMNvBlockNum, NvMBlockUseCrc + NvMBlockCrcType, NvMSelectBlockForReadAll/WriteAll, NvMRamBlockDataAddress, NvMRomBlockDataAddress, NvMWriteBlockOnce, NvMResistantToChangedSw). Bẫy: mất điện giữa ghi → CRC sai (cần redundant); WriteAll quá nhiều block làm shutdown lâu; explicit sync sai gây dữ liệu lệch.

2. MemIf (Memory Abstraction Interface)

Vai trò: trừu tượng hoá nhiều memory abstraction module (Fee & Ea) sau một API thống nhất, để NvM gọi mà không cần biết dữ liệu nằm trên flash hay EEPROM.

DeviceIndex
MemIf định tuyến lời gọi tới đúng module (Fee=device 0, Ea=device 1…) theo DeviceIndex. Cho phép một ECU dùng cả flash (Fee) lẫn EEPROM (Ea).
API thống nhất
MemIf_Read / Write / EraseImmediateBlock / InvalidateBlock / GetStatus / GetJobResult — chỉ forward xuống Fee/Ea theo DeviceIndex.

3. Fee (Flash EEPROM Emulation) — trọng tâm

Vai trò: biến FLASH thành “EEPROM logic” — cho phép đọc/ghi block nhỏ như EEPROM, dù flash không ghi đè byte tuỳ ý. Đây là module “khó” nhất của memory stack.

3.1 Vì sao cần Fee

Flash erase-before-write (bài B1c): chỉ ghi 1→0 theo page, muốn 0→1 phải erase cả sector; chu kỳ erase hữu hạn (~10⁴–10⁵). Nếu mỗi lần cập nhật một biến nhỏ mà phải erase cả sector → vừa chậm vừa nhanh hỏng flash. Fee giải quyết bằng cơ chế ghi tuần tự + garbage collection.

Fee: garbage collection + wear-leveling. Ghi mới = append (tránh erase mỗi lần); sector đầy mới gom block valid sang sector khác rồi erase sector cũ. Luân phiên sector → rải hao mòn.

3.2 Khái niệm cốt lõi

Append / log-structured write
Mỗi lần ghi một block = ghi bản mới vào vùng trống kế tiếp + đánh dấu bản cũ invalid (không erase ngay). Đọc luôn lấy bản valid mới nhất. Nhờ vậy một lần ghi chỉ tốn vài page, không phải erase sector.
Garbage collection
Khi sector hiện tại gần đầy: copy các block valid sang sector dự phòng → erase sector cũ để tái dùng. Phải thiết kế để chịu mất điện giữa chừng (đánh dấu trạng thái sector active/erasable, ghi marker theo thứ tự an toàn) — nếu reset giữa GC vẫn khôi phục được bản valid.
Wear-leveling
Vì flash chỉ chịu ~10⁴–10⁵ chu kỳ erase/sector, Fee luân phiên sector (xoay vòng) để rải số lần erase đều → kéo dài tuổi thọ. Block ghi thường xuyên không “đốt” mãi một sector.
Logical block ↔ physical
App/NvM dùng logical block number ổn định; Fee ánh xạ tới vị trí physical thay đổi sau mỗi lần ghi/GC. Đây là điểm khác cốt lõi so với Ea (EEPROM ghi đè trực tiếp được).
Consistency khi mất điện
Cơ chế ghi marker/header theo trình tự (write block data trước, đánh dấu valid sau) để nếu mất điện thì hoặc thấy bản cũ nguyên vẹn, hoặc bản mới hoàn chỉnh — không bao giờ nửa vời (atomic logic + CRC ở NvM).

API: Fee_Read/Write/EraseImmediateBlock/InvalidateBlock/GetStatus/GetJobResult/SetMode; Fee_MainFunction chạy GC nền. Cấu hình: FeeBlockConfiguration (FeeBlockNumber, FeeBlockSize, FeeImmediateData, FeeNumberOfWriteCycles, FeeDeviceIndex).

4. Ea, Fls, Eep

Ea (EEPROM Abstraction)
Tương tự Fee nhưng trên EEPROM thật (ghi đè byte được) → đơn giản hơn nhiều, ít/không cần garbage collection & wear-leveling phức tạp. Ea_Read/Write/EraseImmediateBlock/InvalidateBlock.
Fls / Eep (MCAL)
Driver HW tầng thấp (bài B1c): Fls cho flash on-chip, Eep cho EEPROM. Read/write/erase, async, sector/page. Fee dùng Fls; Ea dùng Eep.
Quan hệ với DTC (Dem)
Dem lưu DTC/freeze-frame vào NV thường qua NvM block → khi đọc DTC (UDS 0x19) vẫn còn sau khi tắt máy (bài B4).

5. Trước (~2020) → Nay

💾 Memory cho OTA & security
⏪ Trước (~2020)

NvM/Fee chủ yếu lưu calibration, DTC, learned values; EEPROM rời còn phổ biến.

⏩ Nay

Flash lớn, bank A/B cho OTA (ghi firmware mới ở bank rảnh, swap khi xong); KeyM/Csm dùng NV cho khoá; emulated EEPROM tích hợp; quản lý wear & integrity chặt hơn cho xe phần mềm-định-nghĩa.

Vì sao quan trọng: nói được “Fee = log-structured + GC + wear-leveling, và bank A/B cho OTA” cho thấy bạn hiểu cả cơ chế lẫn xu hướng.

6. Tự kiểm tra

Mô tả memory stack từ app xuống HW & vai trò mỗi tầng. Định nghĩa▾

NvM (block/CRC/redundancy/write strategy/queue cho app) → MemIf (route theo DeviceIndex) → Fee (emulate EEPROM trên flash) / Ea (abstraction trên EEPROM) → Fls/Eep (driver HW). EcuM gọi NvM_ReadAll lúc startup, WriteAll lúc shutdown.

Đào tiếp
  • Block type NATIVE/REDUNDANT/DATASET khác gì?
  • RAM/ROM/Administrative block là gì?
Vì sao cần Fee? Garbage collection & wear-leveling hoạt động ra sao? Áp dụng▾

Flash erase-before-write + chu kỳ erase hữu hạn → không ghi đè byte/biến nhỏ trực tiếp. Fee ghi append (bản mới + đánh dấu cũ invalid, không erase ngay); khi sector đầy mới copy block valid sang sector mới rồi erase sector cũ (GC). Luân phiên sector = wear-leveling (rải erase, kéo dài tuổi thọ flash ~10⁴–10⁵ chu kỳ).

Đào tiếp
  • GC mà mất điện giữa chừng thì sao? (thiết kế chịu reset + CRC)
  • Fee khác Ea chỗ nào?
Write strategy immediate vs deferred? Mất điện giữa ghi xử lý sao? Áp dụng▾

Immediate ghi ngay (khẩn); deferred đưa vào queue, NvM_MainFunction xử lý dần (không chặn). Mất điện giữa ghi → CRC bản đang ghi sai → NvM đọc redundant copy (block REDUNDANT) hoặc RestoreBlockDefaults; Fee đảm bảo không để lại block nửa vời (ghi data trước, đánh dấu valid sau).

7. Cheat-sheet 1 trang

Stack

  • NvM → MemIf → Fee/Ea → Fls/Eep
  • App dùng Block ID; HW ẩn dưới
  • ReadAll startup · WriteAll shutdown

NvM

  • Block: NATIVE / REDUNDANT / DATASET
  • RAM + ROM (default) + Administrative block
  • CRC 8/16/32 · queue + priority
  • Strategy immediate vs deferred

Fee (trọng tâm)

  • Vì sao: flash erase-before-write
  • Append + đánh dấu invalid
  • Garbage collection khi sector đầy
  • Wear-leveling (luân phiên sector)

Robustness

  • Redundant copy + CRC → mất điện vẫn khôi phục
  • Logical↔physical block (Fee)
  • Ghi data trước, valid marker sau
  • RestoreBlockDefaults (ROM)

Ea / Fls / Eep

  • Ea: trên EEPROM thật (đơn giản hơn Fee)
  • Fls/Eep: driver HW (bài B1c)
  • Fee→Fls · Ea→Eep

Nay

  • Flash bank A/B cho OTA
  • NV cho khoá (KeyM/Csm)
  • DTC/freeze-frame lưu qua NvM (Dem)
