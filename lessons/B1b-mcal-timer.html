B1b Core AUTOSAR — Module (đào sâu)

MCAL Timer — GPT / PWM / ICU

Ba driver dùng chung khối timer phần cứng nhưng mục đích khác nhau: GPT (đếm→ngắt), PWM (xuất xung), ICU (đo xung vào). Mỗi module một mục đầy đủ — ICU là gốc rễ đo timing SENT.

Nguồn: tên container/param/API/mode đối chiếu AUTOSAR Classic SWS (Gpt/Pwm/Icu Driver) & tài liệu MCAL (TI — đã verify 4 mode ICU) — xem cuối bài.

1. GPT Driver (General Purpose Timer)

Vai trò: dùng kênh timer phần cứng để đếm thời gian và sinh ngắt khi hết hạn — phục vụ delay, đo khoảng thời gian, hoặc làm time base cho BSW. Khác OS Counter ở chỗ GPT là driver phần cứng; OS Counter là đối tượng lịch của OS (thường lấy nguồn từ GPT/SysTick).

1.1 Khái niệm cốt lõi

Channel
Một kênh timer HW độc lập (16 hoặc 32-bit). Mỗi kênh có mode, tần số tick, max value riêng.
Mode: one-shot vs continuous
One-shot: đếm tới target → ngắt → dừng (đo một khoảng/delay đơn). Continuous: hết hạn thì tự nạp lại & đếm tiếp → ngắt định kỳ (vd tick 100 µs). Cấu hình GptChannelMode.
Tick · clock source · prescaler · độ rộng counter
Timer đếm theo clock đã chia qua prescaler; “tick” = đơn vị đếm, độ phân giải = 1/(clock sau prescaler). Counter rộng 16/32-bit giới hạn khoảng đo tối đa (GptChannelTickValueMax); vượt → rollover (phải tính số lần tràn hoặc chọn prescaler/độ rộng phù hợp).
Time elapsed / remaining
Gpt_GetTimeElapsed (đã đếm) / Gpt_GetTimeRemaining (còn lại) — đọc tiến độ runtime, vd để đo thời gian thực thi một đoạn code.
Notification
Callback gọi trong ngữ cảnh ngắt khi timer hết hạn. Phải ngắn & cẩn thận re-entrancy (đăng ký qua cấu hình + Gpt_EnableNotification).
Wakeup capability
Một số kênh GPT có thể chạy ở chế độ sleep (GPT_MODE_SLEEP) và đánh thức MCU khi hết hạn (Gpt_EnableWakeup/Gpt_CheckWakeup) — phối hợp EcuM.
Predef timers
Bộ timer free-running độ phân giải cố định (1 µs / 100 µs / 1 ms / 16-bit/24-bit/32-bit) chuẩn hoá ở các release gần đây — đọc time base nhanh không cần cấu hình kênh riêng.

1.2 API & cấu hình

APIÝ nghĩa
Gpt_Init / Gpt_DeInitKhởi tạo/huỷ các kênh.
Gpt_StartTimer(Ch, Value) / Gpt_StopTimerKhởi động kênh đếm tới Value tick / dừng.
Gpt_GetTimeElapsed / Gpt_GetTimeRemainingĐọc tiến độ.
Gpt_EnableNotification / DisableNotificationBật/tắt callback hết hạn.
Gpt_EnableWakeup / Gpt_CheckWakeupCấu hình/kiểm tra đánh thức.

Cấu hình: GptChannelConfigSet > GptChannelConfiguration (GptChannelId, GptChannelMode [one-shot/continuous], GptChannelTickFrequency, GptChannelTickValueMax, GptNotification, GptEnableWakeup). Bẫy: nhầm tick↔µs (phải quy đổi theo TickFrequency); rollover khi đo khoảng dài; notification re-entrant. Det: GPT_E_UNINIT, GPT_E_PARAM_CHANNEL, GPT_E_PARAM_VALUE.

2. PWM Driver

Vai trò: sinh tín hiệu băm xung với chu kỳ + duty điều khiển được (motor, LED, heater, bơm). Mỗi PWM channel gắn với một khối PWM phần cứng.

PWM. Duty (độ rộng xung) trên một period. Polarity quyết định mức “active”; idle state = mức khi tắt (safe state).

2.1 Khái niệm cốt lõi

Period
Chu kỳ một xung (1/tần số). Với variable-period channel, đổi period chỉ có hiệu lực ở cuối chu kỳ hiện tại (tránh cắt cụt xung đang chạy gây nhiễu).
Duty cycle
Tỉ lệ thời gian mức active trên period. AUTOSAR biểu diễn tuyệt đối 0x0000–0x8000 = 0–100% (0x4000 = 50%) — không phụ thuộc period, nên đổi period không tự đổi duty %.
Polarity
Mức nào là “active”: PWM_HIGH (phần duty ở mức cao) hay PWM_LOW (đảo). Nhầm polarity → motor/LED chạy ngược logic.
Idle state
Mức xuất khi PWM bị đưa về nghỉ bằng Pwm_SetOutputToIdle. Cực kỳ quan trọng cho safe state: khi phát hiện lỗi, đưa PWM về mức tắt an toàn (vd ngắt motor) — liên hệ ISO 26262 (bài H).
Channel class
PWM_FIXED_PERIOD: period cố định, chỉ đổi được duty (đa số chân điều khiển). PWM_FIXED_PERIOD_SHIFTED: period cố định nhưng dịch pha so với chân khác (nếu HW hỗ trợ — vd PWM nhiều pha). PWM_VARIABLE_PERIOD: đổi cả period runtime (vd điều khiển tần số). Gọi SetPeriodAndDuty trên class fixed → Det.
Alignment
Xung căn cạnh (left/edge-aligned: cạnh lên cố định đầu chu kỳ) hay center-aligned (đối xứng quanh giữa). AUTOSAR không định nghĩa alignment trong API — do HW/implementation. Center-aligned hay dùng cho motor (giảm nhiễu & cho phép lấy mẫu ADC đúng giữa).
Edge notification
Callback tại cạnh xung: PWM_RISING_EDGE / PWM_FALLING_EDGE / PWM_BOTH_EDGES. Ứng dụng chính: kích ADC theo pha PWM (đo dòng motor đúng thời điểm) hoặc chẩn đoán tín hiệu (kiểm tra PWM thực sự đổi cạnh).
Autostart
Nếu channel autostart, băm xung bắt đầu ngay trong Pwm_Init; nhưng notification chỉ phát sau khi gọi Pwm_EnableNotification. Edge case duty 0% / 100%: output giữ mức tĩnh (không có cạnh) → notification có thể không xảy ra.

2.2 API & cấu hình

APIÝ nghĩa
Pwm_Init / Pwm_DeInitKhởi tạo/huỷ.
Pwm_SetDutyCycle(Ch, Duty)Đổi duty (0–0x8000), period giữ nguyên.
Pwm_SetPeriodAndDuty(Ch, Period, Duty)Đổi cả period+duty — chỉ variable-period.
Pwm_SetOutputToIdle(Ch)Đưa output về mức idle (safe state).
Pwm_GetOutputState(Ch)Đọc mức hiện tại.
Pwm_EnableNotification(Ch, Edge) / DisableNotificationBật/tắt callback theo cạnh.

Cấu hình: PwmChannelConfigSet > PwmChannel (PwmChannelId, PwmChannelClass, PwmPolarity, PwmIdleState, PwmDutycycleDefault, PwmPeriodDefault, PwmNotification). Det: PWM_E_UNINIT, PWM_E_PARAM_CHANNEL, PWM_E_PERIOD_UNCHANGEABLE (SetPeriodAndDuty trên fixed class), PWM_E_ALREADY_INITIALIZED. Dead-time/complementary output (cho motor) là tính năng HW, cấu hình ngoài API chuẩn.

3. ICU Driver (Input Capture Unit)

Vai trò: đo tín hiệu vào bằng input capture: bắt cạnh, đo period/duty, đếm cạnh, ghi timestamp. Đây là gốc rễ đo timing SENT (khoảng cách giữa các falling edge).

ICU. Capture timestamp tại cạnh (rising/falling/both) → tính period/duty/độ rộng xung hoặc đếm cạnh.

3.1 Khái niệm cốt lõi — 4 measurement mode

Activation edge & default start edge
Cạnh kích: ICU_RISING_EDGE / ICU_FALLING_EDGE / ICU_BOTH_EDGES (đặt bằng Icu_SetActivationCondition). Default start edge (IcuDefaultStartEdge) định cạnh bắt đầu một phép đo (vd đo high-time bắt đầu từ rising).
SIGNAL_EDGE_DETECT
Phát hiện một cạnh → gọi callback IcuSignalNotification. Không đo thời gian, chỉ báo “có cạnh” (vd phát hiện sự kiện/wakeup). Đơn giản & nhẹ nhất.
SIGNAL_MEASUREMENT
Đo tham số thời gian của tín hiệu — chọn một property: period time, high time, low time, hoặc duty cycle. HW tự đo giữa các cạnh; đọc qua Icu_GetTimeElapsed / Icu_GetDutyCycleValues. Dùng đo tần số/duty PWM, tốc độ (bánh răng).
TIMESTAMP
Ghi chuỗi timestamp tuyệt đối của các cạnh vào một buffer (do app cấp). Buffer kiểu linear (đầy thì dừng) hoặc circular (cuộn vòng); sau khi đủ N timestamp gọi IcuTimestampNotification. Đọc vị trí bằng Icu_GetTimestampIndex. Dùng cho tín hiệu phức tạp/không đều — chính là cách giải mã SENT (chuỗi falling edge).
EDGE_COUNTER
Đếm số cạnh (chỉ cạnh đã cấu hình). Icu_EnableEdgeCount / Icu_GetEdgeNumbers. Dùng đo số vòng/tần số bằng cách đếm cạnh trong một cửa sổ thời gian.
Input state
Icu_GetInputState báo trạng thái active/idle của kênh (đã có cạnh từ lần đọc trước chưa) — dùng polling nhẹ thay notification.
Overflow
Nếu khoảng giữa hai cạnh dài hơn tầm đếm của timer → tràn (overflow). Phải chọn prescaler/độ rộng counter sao cho vừa độ phân giải (tick nhỏ) vừa tầm đo (không tràn) — đánh đổi kinh điển khi đo SENT (tick 3–90 µs).
Wakeup
Ở nơi HW hỗ trợ, ICU có thể là wakeup source (cạnh tín hiệu đánh thức MCU); một số HW không hỗ trợ.
🔗

Liên hệ SENT: giải mã SENT = đo khoảng cách giữa các falling edge → dùng TIMESTAMP (ghi chuỗi cạnh rồi tính hiệu) hoặc SIGNAL_MEASUREMENT (period). Hiểu ICU giải thích vì sao SENT nhạy jitter (timing trực tiếp = giá trị) & cách debug bằng UDE/oscilloscope (bài D, F).

Bẫy: overflow khi khoảng cạnh dài; mode loại trừ nhau/kênh; prescaler chọn sai → mất độ phân giải. Det: ICU_E_UNINIT, ICU_E_PARAM_CHANNEL, ICU_E_PARAM_ACTIVATION.

4. Trước (~2020) → Nay

⏱️ Timer trong điều khiển & SDV
⏪ Trước (~2020)

PWM + ICU rời rạc; đo SENT bằng ICU/capture cơ bản.

⏩ Nay

PWM↔ADC↔ICU phối hợp chặt (PWM edge kích ADC đo dòng đúng pha; ICU phản hồi tốc độ) cho motor BLDC/EV; predef timer chuẩn hoá; khối timer phức tạp (RH850 TAUD/TAUJ, GTM) với MCAL safety.

Vì sao quan trọng: trả lời được “PWM center-aligned + edge-notification kích ADC để lấy mẫu dòng đúng giữa xung” cho thấy bạn hiểu vòng điều khiển thật, không chỉ từng driver.

5. Tự kiểm tra

GPT, PWM, ICU khác nhau ra sao? GPT khác OS Counter? Định nghĩa▾

GPT đếm→ngắt (delay/đo khoảng); PWM xuất xung period+duty (output); ICU đo xung vào (cạnh/period/duty/đếm/timestamp). GPT là driver HW; OS Counter là đối tượng lịch của OS, thường lấy nguồn từ một timer HW (GPT/SysTick) để tạo tick cho Alarm/Schedule Table.

Đào tiếp
  • One-shot vs continuous khác gì?
  • Rollover xử lý thế nào khi đo khoảng dài?
PWM channel class & edge notification để làm gì? Duty biểu diễn ra sao? Áp dụng▾

Class: FIXED_PERIOD (chỉ đổi duty), FIXED_PERIOD_SHIFTED (dịch pha nếu HW hỗ trợ), VARIABLE_PERIOD (đổi cả period). Duty tuyệt đối 0x0000–0x8000 = 0–100% (độc lập period). Edge notification (rising/falling/both) dùng để kích ADC theo pha hoặc chẩn đoán. SetOutputToIdle đưa về mức an toàn.

Đào tiếp
  • Đổi period có hiệu lực lúc nào? (cuối chu kỳ hiện tại)
  • Center-aligned vs left-aligned? (impl; center hợp motor)
ICU có 4 mode gì? Đo SENT dùng mode nào và vì sao? Áp dụng▾

SIGNAL_EDGE_DETECT (báo cạnh, không đo time), SIGNAL_MEASUREMENT (period/high/low/duty), TIMESTAMP (chuỗi timestamp cạnh vào buffer linear/circular + notification sau N), EDGE_COUNTER (đếm cạnh). SENT = chuỗi falling edge không đều → dùng TIMESTAMP (ghi cạnh rồi tính hiệu) hoặc SIGNAL_MEASUREMENT period; phải chọn prescaler để vừa độ phân giải (tick 3 µs) vừa tránh overflow.

Đào tiếp
  • Overflow xảy ra khi nào & xử lý sao?
  • Linear vs circular timestamp buffer khác gì?
Làm sao PWM, ADC, ICU phối hợp trong điều khiển motor? Kinh nghiệm▾

PWM (center-aligned) điều khiển cầu công suất; edge notification / HW trigger của PWM kích ADC để lấy mẫu dòng đúng giữa xung (ít nhiễu chuyển mạch); ICU đọc cảm biến tốc độ/vị trí (đo period/đếm cạnh). Cả ba khoá pha với nhau qua khối timer chung.

Đào tiếp
  • Vì sao lấy mẫu ADC đúng giữa xung PWM?

6. Cheat-sheet 1 trang

GPT

  • One-shot vs continuous
  • Tick/prescaler/độ rộng/rollover
  • TimeElapsed/Remaining · notification · wakeup
  • Khác OS Counter (OS lấy nguồn từ timer)

PWM — cơ bản

  • Period + duty (0x0000–0x8000)
  • Polarity · idle state (safe state)
  • Class: fixed / fixed-shifted / variable
  • Đổi period: cuối chu kỳ hiện tại

PWM — nâng cao

  • Alignment left/center (impl; center=motor)
  • Edge notification → kích ADC/chẩn đoán
  • Autostart trong Init; notif sau Enable
  • SetPeriodAndDuty chỉ variable class

ICU — 4 mode

  • EDGE_DETECT (báo cạnh)
  • SIGNAL_MEASUREMENT (period/duty/high/low)
  • TIMESTAMP (chuỗi cạnh, linear/circular)
  • EDGE_COUNTER (đếm)

ICU — chi tiết

  • Activation + default start edge
  • TIMESTAMP = đo SENT
  • Overflow ↔ prescaler/độ rộng counter
  • GetInputState (polling nhẹ)

Phối hợp

  • PWM edge → trigger ADC đúng pha
  • ICU đo tốc độ phản hồi
  • Khoá pha qua timer chung
  • Det: *_E_UNINIT / PARAM_CHANNEL
