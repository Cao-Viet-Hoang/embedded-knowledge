MCU Peripherals & Hardware Debug

Ngoại vi vi điều khiển và debug phần cứng — gắn trực tiếp với RH850, TRACE32, UDE bạn dùng thật. Nắm cơ chế từng ngoại vi và workflow debug để kể được “tôi đã debug thế nào”.

Độ ưu tiên: 🟠 Core Must-tell: TRACE32, UDE Target: RH850 (D3/D4/D5)
📌

Nguồn: đặc tả RH850 (Renesas), watchdog/ADC/clock và TRACE32/NEXUS (Lauterbach) đối chiếu tài liệu nhà sản xuất — xem “Nguồn tham khảo” cuối bài.

1. Ngoại vi cơ bản

Cấu hình hướng (input/output), chế độ (push-pull / open-drain), pull-up/pull-down, tốc độ slew, và alternate function (gán chân cho ngoại vi SPI/UART/CAN…). Điều khiển qua thanh ghi: DIR, OUT, IN, MODE/PMC. Trong AUTOSAR là PORT (cấu hình) + DIO (truy cập).

  • Timer: đếm theo clock; tạo ngắt tràn định kỳ (vd tick OS — trên RH850 là OSTM).
  • PWM: băm xung — điều khiển duty cycle (motor/LED); period & compare value quyết định tần số/độ rộng.
  • Input Capture (ICU): ghi timestamp cạnh tín hiệu → đo tần số/độ rộng xung — chính là cách đo timing SENT.
  • Output Compare: sinh sự kiện/đảo chân khi counter đạt giá trị. RH850 có khối TAUD/TAUJ.

RH850 dùng ADC SAR 12-bit (khối ADCF). SAR = Successive Approximation Register: tìm nhị phân từng bit MSB→LSB bằng so sánh với DAC nội. Quan tâm: độ phân giải, sampling time (phụ thuộc clock ngoại vi), reference voltage, kênh, mode (single/scan/continuous), trigger (SW/HW). DAC: ngược lại, số→analog.

Công thức: digital ≈ round( Vin / Vref × 2ⁿ ); N-bit SAR cần N chu kỳ so sánh (một mẫu/lần, độ trễ thấp → hợp control loop).

Window watchdog mạnh hơn cho safety: refresh quá sớm cũng bị coi là lỗi (code chạy sai nhịp/loop bất thường). Trong AUTOSAR là WDG driver + WdgM (supervision: alive/deadline/logical).

Chuyển dữ liệu memory↔peripheral không cần CPU → giải phóng CPU, tăng throughput (vd nạp buffer ADC/SPI liên tục). CPU chỉ cấu hình nguồn/đích/độ dài rồi nhận ngắt khi xong. RH850 phân biệt DMAC (đầy đủ) và DTS (Data Transfer System, nhẹ). Lưu ý cấu hình: một kênh DMA chỉ cho một module dùng độc quyền.

2. Clock tree & power mode

Một nguồn dao động được PLL nhân lên rồi prescaler chia xuống cho từng miền clock (CPU, bus, ngoại vi):

Clock tree. OSC → PLL (×N) → prescaler chia cho từng miền. Quên bật clock (clock gating) hoặc đặt prescaler sai là lý do kinh điển khiến một ngoại vi “im lặng”.
Nguồn clock
Dao động nội (RC) hoặc thạch anh ngoài; chọn theo độ chính xác cần.
PLL
Phase-Locked Loop — nhân tần số lên (vd 8 MHz → 160 MHz). Phải chờ PLL lock trước khi chuyển CPU sang dùng.
Prescaler
Chia tần số xuống cho từng ngoại vi/bus.
Power mode
RUN / HALT / STOP / STANDBY — tắt dần clock/nguồn để tiết kiệm; wakeup bằng ngắt/sự kiện.

3. RH850 — kiến trúc & functional safety

Dòng MCU ô tô 32-bit của Renesas, lõi RISC độc quyền (G3K/G3M/G4MH), tuân thủ AEC-Q100 và ISO 26262. Bạn làm trên D3/D4/D5 (integrate BSW + test MCAL, debug TRACE32).

  • Lõi: vd G3KH (body/gateway, ~120 MHz, pipeline 5 tầng, ~1 clock/lệnh cơ bản). Dòng cao: U2A tới 4×400 MHz, U2C 2×320 MHz (28 nm).
  • Lockstep: dòng cao chạy dual-core lock-step (2 lõi chạy song song lệch pha, so sánh kết quả) cho ASIL cao; một số tích hợp virtualization để chạy nhiều phần mềm khác ASIL không can nhiễu.
  • An toàn phần cứng: ECC cho RAM/flash, window watchdog (WDTA), clock/voltage monitor.
  • Ngoại vi ô tô: CAN/CAN FD, SENT, LIN, TAUD/TAUJ timer, ADCF, DMAC/DTS.
Dual-core lockstep. Hai lõi chạy cùng lệnh (lệch vài chu kỳ); comparator phát hiện sai khác phần cứng → đưa hệ vào safe state. Đây là một safety mechanism điển hình của ISO 26262 (bài H).
🗣️

Kể được: “Tôi test MCAL và integrate full BSW stack trên RH850 D3/D4/D5, dùng TRACE32 soi register/memory và phân tích trace khi tích hợp; hiểu các cơ chế an toàn phần cứng (lockstep, ECC, window watchdog) vì chúng ảnh hưởng cách test & init.”

4. Lauterbach TRACE32 (must-tell)

Debugger phần cứng (PowerView + PowerDebug) qua JTAG/serial; với RH850 hỗ trợ đầy đủ on-chip breakpoint, run-time memory access, flash programming, và trace NEXUS.

Chuỗi debug. Host → probe → JTAG (debug/breakpoint) + cổng NEXUS (trace). Trace có thể ghi on-chip (buffer nhỏ) hoặc off-chip (Aurora serial / parallel NEXUS AUX: MDO/MSEO/MCKO) cho dung lượng lớn.

Năng lực chính

Breakpoint
Software BP (thay lệnh bằng lệnh break — số lượng không giới hạn, cần ghi được vào RAM) vs on-chip BP (dùng tài nguyên HW, có hạn — bắt buộc cho code chạy từ flash).
Watchpoint
Dừng/ghi nhận khi truy cập dữ liệu một địa chỉ. Tuỳ chọn WATCH = không dừng CPU, chỉ phát “watchpoint-hit message” (non-intrusive với NEXUS).
Register/Memory
Soi & sửa thanh ghi CPU/ngoại vi và bộ nhớ runtime; flash programming.
Trace
NEXUS program + data trace; lọc theo hàm/biến; trace được cả bus master như DMA.

Khi nào dùng cái gì

  • Lỗi logic, biết chỗ → breakpoint.
  • Biến bị sửa bí ẩn → watchpoint (data BP) trên địa chỉ biến.
  • Ngoại vi không hoạt động → soi thanh ghi cấu hình & clock.
  • Lỗi gián đoạn/timing → trace rồi đọc ngược luồng.
  • Code chạy từ flash → phải dùng on-chip BP (SW BP không ghi được flash).

5. UDE Debugger (must-tell) — workflow SENT

UDE (Universal Debug Engine, PLS) bạn dùng để debug timing/signal SENT trên ST & Infineon. Quy trình kể được:

  • Tái hiện & quan sát

    Bắt tín hiệu SENT ở mức xung; xem tick time sau calibration (56 tick), độ dài từng nibble (12–27 tick), khung fast/slow.

  • Đối chiếu kỳ vọng

    So timing đo được với reference manual/spec J2716 để xác định nibble/CRC sai ở đâu.

  • Cô lập HW vs SW

    Chạy cùng software trên target khác (ST↔Infineon) để biết lỗi do phần cứng hay phần mềm.

  • Phân tích tương tác

    Soi thanh ghi/timer (ICU/capture), kiểm tra cấu hình clock/prescaler ảnh hưởng đo timing.

  • Sửa & chốt

    Khắc phục, rồi đưa ca lỗi vào test tự động để bắt sớm lần sau (nối sang bài D).

6. Trước (~2020) → Nay — MCU & debug ô tô

🔧 Lockstep, virtualization & trace tốc độ cao
⏪ Trước (~2020)

MCU body/gateway lõi đơn ~120–240 MHz; trace chủ yếu parallel NEXUS; mỗi chức năng một MCU.

⏩ Nay

MCU zonal đa lõi 320–400 MHz, dual-core lockstep + hardware virtualization (nhiều ASIL trên một chip), trace Aurora Gigabit (AGBT) tốc độ cao; có dòng kèm co-processor RISC-V.

Vì sao quan trọng: hiểu lockstep/virtualization giúp trả lời “làm sao một chip chạy nhiều phần mềm khác mức an toàn” — câu hỏi gắn SDV/zonal.

7. Tự kiểm tra

Window watchdog bắt được lỗi gì mà independent không? Áp dụng▾

Refresh quá sớm: code chạy sai nhịp/lặp bất thường vẫn “nuôi” watchdog. Window WDG chỉ chấp nhận refresh trong cửa sổ [min,max] → bắt cả chạy nhanh lẫn treo. Independent WDG (1 ngưỡng) chỉ bắt treo, nhưng bù lại chạy clock riêng nên reset được cả khi CPU/clock hệ thống chết.

Interviewer đào tiếp
  • Vì sao independent chạy clock riêng lại quan trọng?
  • WdgM trong AUTOSAR giám sát kiểu gì? (alive/deadline/logical)
SAR ADC hoạt động ra sao? Vì sao hợp control loop? Định nghĩa▾

Tìm nhị phân: SAR đặt MSB=1, DAC nội tạo điện áp so với Vin qua comparator; nếu DAC > Vin thì xoá bit, ngược lại giữ; lặp tới LSB. N-bit cần N chu kỳ so sánh, một mẫu/lần, độ trễ thấp & tất định → hợp vòng điều khiển. Đổi lại tốc độ thấp hơn pipeline/flash ADC.

Interviewer đào tiếp
  • Sampling time ảnh hưởng gì? (quá ngắn → chưa nạp đủ tụ S/H → sai số)
  • 12-bit, Vref=5V thì 1 LSB ≈ ? (≈1.22 mV)
Khi một ngoại vi “im lặng”, bạn kiểm tra gì đầu tiên? Kinh nghiệm▾

Thứ tự: (1) clock ngoại vi đã bật chưa (clock gating) + PLL lock; (2) cấu hình chân (alternate function/PORT); (3) thanh ghi enable + prescaler; (4) ngắt/cờ trạng thái. Dùng TRACE32 soi thanh ghi cấu hình so với datasheet — đa số lỗi là quên bật clock hoặc sai chân.

Interviewer đào tiếp
  • Làm sao xác nhận PLL đã lock? (đọc cờ lock / đo clock out)
Breakpoint khác watchpoint thế nào? SW BP vs on-chip BP? Định nghĩa▾

Breakpoint dừng tại lệnh/địa chỉ code; watchpoint (data BP) dừng/ghi nhận khi truy cập dữ liệu. SW BP thay lệnh trong bộ nhớ bằng lệnh break (không giới hạn, cần ghi được vào RAM); on-chip BP dùng tài nguyên HW (có hạn) — bắt buộc khi code chạy từ flash (không ghi đè được).

Interviewer đào tiếp
  • WATCH (non-intrusive) khác breakpoint thường ra sao?
Vì sao DMA hữu ích cho ADC tốc độ cao? Áp dụng▾

DMA chuyển mẫu ADC vào buffer bộ nhớ mà không làm CPU bận từng mẫu → CPU rảnh, tránh mất mẫu khi sampling nhanh. CPU chỉ cấu hình + nhận ngắt khi đầy buffer. (RH850: DMAC/DTS, một kênh cho một module.)

Interviewer đào tiếp
  • DMA gây vấn đề gì với cache/coherency?

PLL nhân tần số lên (cần chờ lock); prescaler chia tần số xuống cho từng bus/ngoại vi.

8. Cheat-sheet 1 trang

Ngoại vi

  • GPIO: PORT (cấu hình) + DIO (truy cập)
  • Timer/PWM/ICU/Output Compare
  • ADC SAR 12-bit: binary search, N chu kỳ
  • DMA: memory↔periph không CPU (DMAC/DTS)

Watchdog

  • Independent: 1 ngưỡng, clock riêng
  • Window: [min,max] — bắt cả quá sớm
  • RH850 = WDTA; AUTOSAR = WDG + WdgM

Clock/power

  • OSC → PLL ×N → prescaler → domain
  • RH850: hệ số trong option bytes
  • Im lặng = quên clock gating / sai chân
  • RUN/HALT/STOP/STANDBY

RH850

  • Lõi G3K/G3M/G4MH, RISC, AEC-Q100
  • Dual-core lockstep (ASIL cao)
  • ECC RAM/flash, virtualization (dòng mới)
  • D3/D4/D5: BSW integ + MCAL test

TRACE32

  • SW BP (RAM, vô hạn) vs on-chip BP (flash, có hạn)
  • Watchpoint = data access; WATCH non-intrusive
  • Trace NEXUS: on-chip ↔ off-chip (Aurora/AUX)
  • Soi register/memory, flash program

UDE (SENT)

  • Bắt xung → so J2716
  • Cô lập HW/SW (cross-target ST↔Infineon)
  • Soi ICU/timer/clock
  • Sửa → đưa vào test tự động
